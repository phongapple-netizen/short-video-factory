# 竖屏知识视频制作规范 v1

适用：数学、奥数、物理、化学、历史事件等抖音知识讲解视频。
来自已完成的正方体十字孔视频经验。配置见 `douyin-profile.json`；选题填 `BRIEF_TEMPLATE.md`。

## 1. 必须固定的交付边界

| 项目 | 标准 |
| --- | --- |
| 画幅与帧率 | 1080×1920，30fps |
| 关键内容安全区 | x=60–930，y=160–1500 |
| 字幕位置 | 框底边≤1500，默认高度120，最多两行 |
| 最小字号 | 实际可见字号≥30px；缩放动画后也要满足 |
| 开场主标题 | 第一帧出现，默认88px起，按安全区换行 |
| 页脚 | 不放底部小字；必要的单位、条件移入正文或字幕 |
| 导出 | MP4，H.264，CRF16，yuv420p，BT.709有限范围，AAC |
| 成品响度 | −15 LUFS，容差±0.3；编码后真峰值≤−1.5 dBTP |
| 文字可读性 | 正文/字幕对比度至少4.5:1；大标题至少3:1；关键算式不降透明度 |

安全区是本账号目前采用的保守边界，不是所有设备、所有版本抖音UI的永久保证。平台UI变化时更新配置版本；发布前仍查看手机预览。
普通背景和装饰可以铺满画幅，关键文字、模型、箭头、网格、图例和数字必须在安全区内。字幕所占区域单独预留，不能与正文重叠。

## 2. 固定工作流程

1. 阅读现有项目与composition；已有视频的修改沿用当前组件，保留可回退版本。
2. 先写“本条只讲清什么”，核对事实、公式、日期、单位、条件与参考资料。
3. 建立内容数据和图解模型；先确认图本身正确，再做动画、美化和配音。
4. 字幕与配音分别存 `text`、`voiceText`。字幕用阿拉伯数字/公式；配音保留自然读法。
5. 为每句生成或复用音频，用真实音频时长安排字幕与动作，再确定分镜长度。避免先锁死全部场景再强行加速解说。
6. 用 `npx remotion still` 检查首帧、开场结束、每个场景、动画途中、结尾与封面。不能只检查另做的示意Still。
7. 确认模型/内容、安全区、字号、遮挡和节奏后，渲染完整视频。
8. 两遍响度归一化后，以 `ffprobe` 检查编码/尺寸/帧率/时长，以 `ebur128=peak=true` 测量最终AAC；不能只测原配音。
9. 交付视频、独立封面PNG、发布文案、可编辑项目与检查报告。说明修改文件、复现命令及实际限制。

配音服务失败时保护已有资产，先写临时文件，成功后再替换。字幕起止时间从音频测量生成，动画关键动作从同一时间轴读取。
需要背景音乐时，在混音后测整条成品；音乐不能盖过讲解。

## 3. 按选题调整的部分

| 项目 | 默认 | 调整原则 |
| --- | --- | --- |
| 总时长 | 60–65秒 | 可以按知识点改成30秒、90秒或拆成系列，记录本条目标即可 |
| 开场 | 3–6秒 | 一个问题、现象、冲突或悬念；第一帧就有可读主标题和主体画面 |
| 中段 | 无固定秒数 | 根据真实配音、推理步骤和画面复杂度分配 |
| 结尾 | 3–5秒 | 给出结论，短动画收束；评论提示按内容选择 |
| 分镜 | 不固定五段 | 每段都服务于一个明确理解步骤，复杂的步骤留出观察时间 |
| 画风 | 清晰、统一、留白 | 图解、地图、时间线、实验示意、档案照片按学科选择 |
| 配音 | 默认晓晓普通话 | 音色可统一，语速和情绪按主题调整，优先精简文案而非过度加速 |
| 品牌 | 可配置 | 不把“几何实验室”写死到物理、化学、历史视频里 |

不统一锁死：63秒总长、125→100→86→76时间轴、五层排布、蓝绿黄三组颜色、固定答案弹出、每段都用立方体。
平台参数是共同底座；学科内容作为各自的场景组件。

## 4. 各学科的准确性边界

| 学科 | 图解方法 | 必查项 |
| --- | --- | --- |
| 数学/奥数 | 几何、数轴、格子、数表、逐步推导 | 图形尺寸/关系正确；计数来自模型；单位完整；结果独立验算 |
| 物理 | 现象→模型→矢量/曲线→规律 | 力和运动方向不混淆；量纲、坐标轴、边界条件正确；慢动作/不按比例图示注明 |
| 化学 | 宏观现象→粒子示意→反应式 | 原子/电荷守恒；反应式配平；状态、条件、现象与结论一致；示意图不冒充实测结果 |
| 历史 | 问题→背景→事件时间线/地图→影响 | 日期、人物、地点与资料一致；事实、解释、争议分清；重建画面标注“示意/重建” |

历史年份是事件数据，不是视频播放时间；地图坐标与动画坐标同样分开保存。
事实或计算没核实时不要先用肯定字幕和配音定稿。来源记录到项目文档，包括链接或书名、章节/页码及对应结论。

## 5. 可复用组件边界

通用：安全区常量、页眉、标题、字幕、图例、数字/重点强调、场景切换、声音时间轴、封面与导出/检查工具。
学科专用：几何布尔模型、受力图、物理数据曲线、分子/反应模型、历史事件与地图。
保持通用组件读取配置，学科场景读取内容数据；不要把答案、日期、计算结果复制硬编码到多个视图。

建议每个新项目保留以下结构，不要求立即重构已有项目：

```
src/profile.json       # 从本配置复制，作为本项目唯一的平台参数来源
src/content.json       # 问题/事实/模型输入/结论/来源
src/captions.json      # text、voiceText、audio、start、end、duration
src/timeline.json      # 场景时间，依据音频与讲解步骤确定
src/scenes/            # 学科场景
src/components/        # 共用画面组件
public/audio/          # 每句配音、可选音乐
out/                   # 成品、封面、实际帧、检查报告
```

当前数学项目仍使用自己的 `src/layout.ts`，数值与本配置一致；本规范没有改变它的运行代码。
新项目可复制本配置并从单一文件读取。这个JSON目前是默认参数清单，不宣称已接入跨项目自动流水线。

## 6. 验收与复现

先验证内容模型，再检查实际帧，最后验证编码后的文件。自动像素检查可发现越界，但不能代替人看图、核对语义或检查手机端UI。
最后一段不能因音频填充而留下长时间静止；配音应完整，字幕不提前消失，图解动作应与对应解说对齐。

推荐导出参数：

```
npx remotion render src/index.tsx <CompositionId> out/raw.mp4 --crf=16 --pixel-format=yuv420p --codec=h264 --audio-codec=aac --color-space=bt709
```

浏览器路径按运行环境选择，不把 `/usr/bin/chromium` 当成跨平台固定值。
本次发现仅设 `yuv420p` 时默认色彩设置可能仍被识别为 `yuvj420p`，因此显式选BT.709并检查最终文件。
响度处理目标可设TP=−1.8留AAC编码余量，验收以最终真峰值≤−1.5为准。

本规范保存在当前工作区。以后开新项目/新对话时提供这份文件或要求先读取它，避免假定其他工作区会自动保留这些约定。
